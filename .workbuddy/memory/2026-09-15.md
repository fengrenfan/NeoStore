## 新项目：NeoStore（轻量单店 DTC 跨境独立站）

用户确认的决策：单店 DTC 形态 / FastAPI + React / 先做通用多语言框架 /
方案 A 前端结构（Next.js 店面 + 独立 Vite 后台）/ PostgreSQL / 首期最小可用闭环。

设计文档已落地并提交：
`docs/superpowers/specs/2026-09-15-neostore-design.md`
git 已 init，首个 commit `60fd0bd`。

关键设计决定：
- i18n 用独立翻译表（`*_translation` + UNIQUE(entity_id, locale)），不用 JSONB 内嵌字段。
- 多币种：显式定价优先，缺失时按汇率换算兜底；换算结果按目标币种 decimal_places 取整。
- Region = 币种 + 语言集合 + 税率 + 可用支付方式的聚合。
- 金额一律 Decimal，计算收敛到 `pricing.calculate()` 单一入口。
- 库存用 `SELECT ... FOR UPDATE` 行锁 + reserved 预占防超卖。
- 下单接口支持 `Idempotency-Key` 防重复下单。
- domain 层禁止 import fastapi / 直接拿 Session，持久化走 repository 接口。

状态：**设计待用户评审**，评审通过后进入实施计划（M0–M4）。

### 今天踩到并修掉的真问题（都值得记住）

1. **冒烟测试被"陈旧数据库"骗过**：`smoke.sh` 原来删共享的 `smoke.db`，一旦删除没落地
   （被拒绝、残留 `-wal`、旧进程抱着旧 inode），本次运行就继承了上一轮的订单，
   于是 checkout 返回的是上轮那笔**已支付**订单，断言全在描述错误的世界。
   修法：每轮用唯一 `smoke-<pid>.db` + 断言"0 订单 3 商品" + 端口被占用时直接退出。
2. **时间戳时区**：SQLite 的 `DateTime(timezone=True)` 回来是 naive，浏览器把
   `2026-09-15T07:51:52` 当本地时间读，CST 下显示差 8 小时。加了 `app/core/serialization.py`
   的 `UtcDatetime`（`+00:00`），PostgreSQL 与 SQLite 行为一致。
3. **`docker compose` 里 `app.seed --if-empty` 这个参数并不存在**，argparse 会非零退出 →
   api 容器起不来。已删（seed 本身幂等）。
4. 沙箱内 npm install 会被文件系统 broker 拒绝 → `scripts/sandbox-fs-guard.cjs`（`node -r` 预加载，
   限制 mkdir/rename/symlink 并发）是唯一可行路径。

### 验证方式（以后照做）

## 部署到服务器 /home/app/store

服务器现状（先查再动，避免踩别人）：

- 宿主机 nginx 独占 **80/443**，已有三个站点：`xiaodigua.shop`、`blog.xiaodigua.shop`、
  `quant.xiaodigua.shop`，证书都在 `/etc/letsencrypt/live/<域>/`（Certbot 管的）。
- 已占端口：80/443、8088(blog-nginx)、8090(quant-web)、18000(quant-engine)、
  18081(quant-backend)、8080/8081、3001、9090。→ NeoStore 只能换一套端口。
- **内存本来就紧**：3.7 G 物理内存只剩 1.28 G，swap 6 G 已用掉 2.7 G。
  Docker 有 ~11 GB 可回收空间（镜像 10.4 GB / 构建缓存 5.7 GB），磁盘 81% 但够用。

落地方式：

- **代码用 git bundle 传**（沙箱和服务器都连不上 github.com）：`git bundle create --all`
  → scp → 服务器 `git clone /tmp/neostore.bundle .`。校验：193 个跟踪文件、HEAD `3df2cd4`、
  `git status` 干净、`git fsck` 无输出。
- `/home/app/store` 原本是 root 的空目录，先 `chown ubuntu:ubuntu`。ubuntu 在 docker 组，
  不用 sudo 就能跑 compose。
- **写了两份服务器专属文件（都在 .gitignore 里，不入库）**：
  - `backend/.env`：随机 `JWT_SECRET`（64 hex）+ 随机管理员密码（19 位），
    `CORS_ORIGINS` 含 `http://124.222.204.236:8091`。
  - `docker-compose.override.yml`：Caddy 改到 **8091:80**，`api/storefront/admin` 只绑
    127.0.0.1（18082 / 3002 / 8092），db/redis/worker 不发布端口。
- **踩坑：Compose 对 `ports` 这类序列是「合并」不是「替换」**。override 里直接写 `ports:`
  会变成 80+443+8091 三个都绑，Caddy 必然撞宿主机 nginx 起不来。必须用 `!override`
  标签（Compose ≥ 2.24.4，线上是 2.40.3 支持）整段替换。
- **storefront 的浏览器端地址故意留空**：`NEXT_PUBLIC_API_BASE_URL: ""`，
  于是 `baseUrl()` 返回 `""`，fetch 拼出 `/api/v1/...` 相对路径 → 同源。
  好处是同一个镜像放到端口 / 子域名 / HTTPS 后面都不用重新构建。
  （`??` 不会把空字符串当 nullish，所以空串能穿过默认值。）
  服务端组件仍走 `API_BASE_URL=http://api:8000`，不受影响。这条和 admin 那个
  「同源 `/api/v1`，一份产物走天下」的设计是一致的。
- **`store.xiaodigua.shop` 目前没有 DNS 记录**，所以暂时只能 `http://124.222.204.236:8091`。
  想上 HTTPS 子域名需要：DNSPod 加 A 记录 → 加 nginx 站点 → certbot 签证书。
- 构建用 `COMPOSE_PARALLEL_LIMIT=1` 串行，避免几个 node/python 构建同时抢那 1.2 G 内存。
